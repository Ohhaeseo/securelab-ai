# 0001. 세션 쿠키 기반 인증

- 상태: 채택 (기획서 6장)
- 날짜: 2026-11-20

## 배경

테스트 클라이언트와 Swagger로 API를 호출하고, 로그아웃 시 즉시 세션을 끊을 수 있어야 한다. 단일 로컬 서버로 운영하며 분산 환경은 비목표다.

## 결정

Spring Security의 서버 세션 인증을 쓴다.

- 세션 쿠키에 HttpOnly, SameSite를 적용하고, HTTPS 배포 시 Secure를 강제한다.
- 로그인 성공 시 세션 ID를 바꿔 세션 고정 공격을 막는다.
- 브라우저 기반 상태 변경 요청에는 CSRF 방어를 적용한다.
- 로그아웃 시 서버에서 세션을 무효화한다.

## 검토한 대안

- **JWT (Bearer 토큰):** CSRF 부담은 줄지만, 만료 전 토큰을 끊으려면 차단 목록이 필요하고 토큰을 클라이언트에 안전하게 보관하는 문제가 생긴다. 이 프로젝트의 목표(인가 설계와 측정)에 비해 복잡도만 늘어난다.

## 결과

- CSRF 토큰 전달 방식을 정해야 한다. 권장: `CookieCsrfTokenRepository` + `GET /api/v1/auth/csrf` (I-4, 11/26 결정).
- JSON 로그인 컨트롤러를 직접 만들면 SecurityContext를 세션에 저장하는 처리를 명시해야 한다.
- k6와 통합 테스트는 쿠키와 CSRF 토큰을 유지하도록 작성해야 한다.
- 여러 인스턴스로 늘리려면 세션 저장소(예: Redis)가 필요하지만 이번 범위는 아니다.
