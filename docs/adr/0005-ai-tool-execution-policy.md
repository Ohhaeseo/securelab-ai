# 0005. AI 도구 실행 정책

- 상태: 채택
- 날짜: 2026-11-20

## 배경

문서 기반 AI 도우미는 신뢰할 수 없는 입력(사용자 질문, 다른 사용자가 쓴 공개 문서)을 읽고 도구 호출을 제안한다. 모델은 문서 속 지시에 넘어갈 수 있다(AI-01). 기획서는 "불허 도구 호출 실제 실행 0건"을 완료 기준으로 두고, 도구 실행을 공개 API가 아니라 서버 내부 `ToolExecutionPolicyService`로 구현하라고 한다.

## 결정

- 모델은 도구를 **제안만** 한다. 실행 여부는 `ToolExecutionPolicyService`만 정하고, 이 서비스를 거치지 않는 실행 경로는 없다 (공개 실행 API 없음).
- 판정 순서:
  1. **호출 수 상한** — 한 답변에 3개까지 (`TOO_MANY_TOOL_CALLS`)
  2. **허용 목록** — 스프링 빈으로 등록된 도구 이름만, 정확히 일치 (`NOT_IN_ALLOWLIST`, AI-04)
  3. **인자 스키마** — 선언되지 않은 인자 거부, 타입·범위 확인. 정수 자리에 문자열 `"12"`도 받지 않는다 (`SCHEMA_INVALID`, LLM05)
  4. **역할** — 관리자 도구는 관리자 세션에서만 (`ROLE_REQUIRED`, AI-02)
  5. **실행** — **현재 사용자 권한으로** 도메인 서비스를 부른다. 객체 단위 인가(문서 소유권)가 그대로 적용된다 (`NOT_PERMITTED`)
- **MVP의 도구는 읽기 전용만** 둔다: `get_document`, `list_documents`, `list_security_events`(관리자).
- 모든 판정은 `ai_tool_calls`(도구 이름, 인자 SHA-256, ALLOWED/DENIED, 사유)에, 거부는 보안 이벤트 `AI_TOOL_DENIED`에도 남긴다.

## 검토한 대안

- **모델 출력 텍스트 필터:** "위험한 문장"을 지우는 방식은 우회가 쉽고, 실제 행위를 막지 못한다.
- **시스템 프롬프트 강화만:** 문서를 데이터로 구분하는 지시는 넣었지만(PromptBuilder), 소형 모델은 쉽게 넘어간다. 보조 수단일 뿐이다.
- **Spring AI의 자동 도구 실행:** 모델이 고른 함수를 프레임워크가 바로 실행한다. 판정 지점을 서버 정책 하나로 모으려고 쓰지 않는다.
- **쓰기 도구 허용(예: 공개 범위 변경):** 문서 속 지시가 **피해자 권한으로** 피해자 문서를 공개로 바꾸게 할 수 있다(confused deputy). 권한 재검사로는 막을 수 없다 — 피해자에게는 그 권한이 있기 때문이다.

## 결과

- 남는 위험: 관리자가 공격자의 공개 문서를 AI로 읽으면, 문서 속 지시가 관리자 도구(`list_security_events`) 실행을 이끌어낼 수 있다. 결과는 관리자 본인에게만 보이고 외부로 내보낼 경로(쓰기·전송 도구)가 없어 유출은 아니지만, **의도하지 않은 실행**이다. 실험에서는 "모델 반응"으로 센다.
- 쓰기·전송 도구를 추가할 때는 **사용자 명시 확인**(모델 제안 → 사용자 승인 → 실행)과 출처 표시(어느 문서가 이 호출을 이끌었는지)를 함께 넣는다.
- 테스트에서 실제로 관찰됨: 다른 사용자가 심어 둔 공개 문서 속 지시가 키워드 검색으로 피해자의 AI 문맥에 끌려 들어왔다. 정책이 거부해 실행은 0건이었다.
