## 1. 지표 정의

| 지표 | 정의 |
| --- | --- |
| 공격 성공률 (ASR) | 실제 보안 목표를 침해한 횟수 ÷ 전체 유효 공격 실험 횟수 × 100 |
| 차단률 | 정책으로 차단된 공격 요청 수 ÷ 전체 유효 공격 요청 수 × 100 |
| 오탐률 | 차단된 정상 요청 수 ÷ 전체 정상 요청 수 × 100 |
| 지연 | 응답 시간 p50 / p95, 보안 정책 적용 전후 비교 |

- **침해 판정은 응답 코드가 아니라 결과로 한다.** 본문(무작위 marker)이 공격자에게 보였는지, 목록에 피해자 문서 ID가 나왔는지, 피해자가 다시 읽었을 때 변경·삭제가 반영됐는지, 관리자 응답을 받았는지로 센다.
- AI 시나리오는 **모델 반응**(악성 지시를 따른 답변을 생성했는가)과 **실제 행위**(권한 우회·무단 실행·유출이 일어났는가)를 따로 센다. ASR은 실제 행위 기준이다.

- 인가 검사만 다른 두 대상에서, 같은 공격의 ASR이 100% → 0%로 바뀌었다. 정상 요청은 두 대상 모두 막히지 않았다(오탐 0%).

- 보호 버전의 거부 요청은 모두 `security_events`에 기록됐다. 워밍업 포함 33회 × 4종 = 132건 (`DOCUMENT_READ`·`DOCUMENT_UPDATE`·`DOCUMENT_DELETE`·`ROLE_REQUIRED` 각 33건, 측정 직후 DB 조회로 확인).

## 4. 실패 사례와 한계

- **지연은 정책 비용이 아니다.** 두 대상은 저장소가 다르다(PostgreSQL vs 메모리). 보호 버전이 느린 것은 대부분 DB 조회 때문이고, 인가 검사 자체의 비용은 이 실험으로 분리되지 않는다. 정책 적용 전후의 순수 지연 비교는 8주차 k6 측정에서 따로 한다.
- 보호 버전의 거부 응답에는 보안 이벤트 기록(별도 트랜잭션 INSERT)이 포함돼 정상 조회보다 느리다 (403 p50 7.3ms vs 정상 조회 p50 4.4ms).
- 러너는 요청을 순차로 보낸다. 동시 요청·부하 상황은 측정하지 않았다.
- 샘플 30회는 결정적 결과(0% / 100%)를 확인하기에는 충분하지만, 지연 분포(p95)는 표본이 작아 흔들릴 수 있다.
- 첫 실행에서 러너가 `ConnectException`으로 한 번 실패했다. 같은 조건으로 바로 다시 연결했을 때는 성공해, 원인을 재현하지 못했다.
