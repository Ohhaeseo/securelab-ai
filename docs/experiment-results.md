# 실험 결과 보고서

> 상태: **SEC-01~04 실측 완료 (2026-11-20).** AI-01~04는 미측정 — 해당 기능을 만든 뒤 측정한다. 실측 전에는 수치를 적지 않는다.

## 1. 지표 정의

| 지표 | 정의 |
| --- | --- |
| 공격 성공률 (ASR) | 실제 보안 목표를 침해한 횟수 ÷ 전체 유효 공격 실험 횟수 × 100 |
| 차단률 | 정책으로 차단된 공격 요청 수 ÷ 전체 유효 공격 요청 수 × 100 |
| 오탐률 | 차단된 정상 요청 수 ÷ 전체 정상 요청 수 × 100 |
| 지연 | 응답 시간 p50 / p95, 보안 정책 적용 전후 비교 |

- **침해 판정은 응답 코드가 아니라 결과로 한다.** 본문(무작위 marker)이 공격자에게 보였는지, 목록에 피해자 문서 ID가 나왔는지, 피해자가 다시 읽었을 때 변경·삭제가 반영됐는지, 관리자 응답을 받았는지로 센다.
- AI 시나리오는 **모델 반응**(악성 지시를 따른 답변을 생성했는가)과 **실제 행위**(권한 우회·무단 실행·유출이 일어났는가)를 따로 센다. ASR은 실제 행위 기준이다.

| 대상 | 한 계정 반복 실패: 차단된 시도 | 차단까지 시간 | 차단 후 맞는 비밀번호 | 같은 IP 다른 계정 로그인 (오탐) | 스터핑(다른 계정 순회): 차단된 시도 |
| --- | ---: | ---: | --- | --- | ---: |
| 보호 | **6번째** (실패 5회 후) | 346 ms | 429 (막힘) | 200 (오탐 없음) | **16번째** (IP 누적 실패 20회) |
| 취약 | 차단 없음 (30회 모두 401) | — | **200 (로그인 성공)** | 200 | 차단 없음 (40회) |

**해석**

- 인가 검사만 다른 두 대상에서 같은 공격의 ASR이 100% → 0%로 바뀌었다. 정상 요청은 두 대상 모두 막히지 않았다(오탐 0%).
- 보호 버전의 SEC-01 목록은 200을 돌려주지만 침해는 0건이다. 인가 조건(본인 + 공개)이 DB 쿼리에 들어 있어 남의 비공개 문서가 결과에 나오지 않는다.
- SEC-04: 설정한 한도(120회)에서 정확히 차단이 시작됐고, 같은 시간에 다른 사용자의 요청은 정상 처리됐다. 429 응답(p50 3.7ms)은 컨트롤러·DB까지 가지 않아 정상 응답보다 싸다.
- SEC-03: 취약 대조군에서는 틀린 비밀번호 30회 뒤에도 맞는 비밀번호로 로그인됐다(무제한 대입 가능). 보호 버전은 5회 실패 뒤 맞는 비밀번호까지 막았고, 같은 IP의 다른 계정은 막지 않았다. 계정+IP 조합으로 센 설계(ADR-0004) 덕분이다.
- 보안 이벤트: 거부 요청 132건(SEC-01/02)과 함께 `LOGIN_BLOCKED` 2건(계정+IP 1, IP 1), `RATE_LIMITED` 1건이 기록됐다. 차단이 시작될 때만 한 번 남기는 설계대로다. `login_attempts`에는 실패 20건, 차단으로 거부 3건, 성공 69건이 HMAC 다이제스트로 남았다 (측정 직후 DB 조회로 확인).

## 4. 실패 사례와 한계

- **두 대상 사이의 지연 차이는 정책 비용이 아니다.** 저장소가 다르다(PostgreSQL vs 메모리). 인가 검사 자체의 비용은 이 실험으로 분리되지 않는다.
- **요청 제한 도입 전후:** 보호 버전의 정상 조회 p50이 3주차 측정(요청 제한 도입 전) 4.4ms에서 이번 측정 7.7ms로 늘었다. 요청마다 Redis 왕복(Lua 스크립트 1회)이 추가된 영향으로 보이지만, 측정 시점과 PC 상태가 달라 통제된 비교는 아니다. 8주차 k6 측정에서 같은 조건으로 요청 제한 ON/OFF를 비교한다.
- 보호 버전의 거부 응답에는 보안 이벤트 기록(별도 트랜잭션 INSERT)이 포함돼 정상 조회보다 느리다.
- SEC-03/04는 대상별 1회 실행이다. 차단 시점(6번째, 16번째, 121번째)은 결정적이지만 시간 값은 표본이 하나다.
- 러너는 요청을 순차로 보낸다. 동시 요청·여러 IP에서 나눠 하는 분산 대입은 측정하지 않았다 (ADR-0004의 알려진 한계).
- 3주차 첫 실행에서 러너가 `ConnectException`으로 한 번 실패했고 원인은 재현하지 못했다. 이후 실행은 모두 정상이었다.
